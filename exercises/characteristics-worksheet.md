# Architecture Characteristics Worksheet

Use this worksheet for the [architecture kata](./architecture-kata.md). Print it or copy it into your team's notes.

## Candidate characteristics

| Characteristic | What it means | Evidence in the brief? (quote it) |
| --- | --- | --- |
| Availability | The system is up when users need it | |
| Scalability | Handles more users or data by adding resources | |
| Elasticity | Handles sudden bursts and scales back down | |
| Performance | Responds fast enough under expected load | |
| Fault tolerance | Keeps working when parts of it fail | |
| Data consistency | Every reader sees correct, agreed-upon data | |
| Security | Protects data and functions from misuse | |
| Maintainability | Easy to change safely | |
| Testability | Easy to verify that it works | |
| Deployability | Easy and low-risk to release | |
| Extensibility | Easy to add new variants or features | |
| Observability | You can tell what the system is doing and why | |
| Cost | Affordable to build and operate | |
| Customizability | Users or tenants can tailor behavior or look | |
| Simplicity | Few moving parts for the team to understand and run | |
